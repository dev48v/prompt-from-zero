PROMPTFROMZERO · DAY 65

🔀 Exemplar ordering — the same few-shot examples, shuffled, and the answer changes. Sixty-four days of this series have treated a prompt as a set of demonstrations. It is a sequence, and three separate biases ride on the order: recency (the last example weighs most), majority label (an unbalanced set drags the prediction toward whichever label appears more), and common token (a label that is simply a more likely string wins ties). This page implements a calibrated classifier whose biases are declared rather than emergent, then enumerates all 720 permutations of a 6-shot prompt and shows the accuracy spread — best order against worst, on identical content. It also implements contextual calibration (Zhao et al. 2021): estimate the bias by feeding a content-free input, divide it out, and watch the spread collapse. Then the finding that rewrote this page — I set out to show that calibration helps but does not eliminate, measured it, and got exact elimination. That is not a bug: a bias which is an additive constant in logit space is precisely what a content-free probe measures, so dividing it out is exact. What survives calibration is only the bias a content-free input cannot exhibit — the part that needs content to exist at all. Both halves are on the page, and both are asserted. Pure vanilla JavaScript, one file, offline.

A sentiment classifier with three declared biases. Nothing here is emergent — every coefficient is a slider, which is what makes the effects measurable instead of anecdotal.

A prompt is a sequence, and you have been treating it as a set


      
Sixty-four techniques into this series, few-shot prompting has been described the way
      everyone describes it: pick some good examples, put them in, done. Pick which
      examples has had a whole day to itself (dynamic few-shot, Day 58). Pick what order
      has had none, and it moves the number more than most rewording does.


      
Lu et al. (2021) found accuracy swings from near-random to near state-of-the-art across
      permutations of the same examples. Not different examples. The same ones, in
      a different order.


      
Three biases, and they are separable


      
The instinct is to call this "the model is weird". It is not weird, it is three named
      effects that Zhao et al. (2021) isolated, and this page implements them as three separate
      dials so you can see which one is doing the damage:


      
    
        
  • Recency bias. The example nearest the query counts most. Put your
        negatives last and the model leans negative.
    • 
        
  • Majority-label bias. An unbalanced demonstration set drags predictions
        toward whichever label appears more — even when the test set is balanced.
    • 
        
  • Common-token bias. A label that is simply a more probable string wins
        the close calls. "Positive" versus "Negative" is not a fair coin to a language model.
    • 
      


      
Turn any one of them to zero on the page and the corresponding structure in the
      permutation histogram disappears. That is the argument for them being three things rather
      than one vague thing.


      
720 permutations, because 6! is small enough to be exhaustive


      
Six examples have 720 orderings, which is cheap enough to enumerate rather than sample. So
      the page does not report "we tried a few orders and it varied" — it reports the
      full distribution, the exact best ordering, the exact worst, and the spread
      between them.


      
Exhaustive matters here because the interesting question is the tail. A mean over
      sampled orderings hides the fact that some specific arrangement of your examples is much
      worse than the rest, and in production you did not sample — you picked one and shipped it.


      
Contextual calibration: measure the bias directly


      
The fix is better than it sounds. If you feed the prompt a content-free
      input — the string "N/A", or an empty string — then whatever the model predicts is
      entirely bias, because there was nothing to classify.


      
p_cf = model(prompt, "N/A")          // pure bias, no content
W    = diag(1 / p_cf)                // the correction
p̂    = normalize(W · model(prompt, x))


      
One extra call per prompt, not per query — the correction is a property of the prompt, so
      you compute it once and reuse it. That is what makes this practical rather than a paper trick.


      
And the part the summaries leave out


      

        
This page was rewritten by its own measurement. I
        expected "calibration helps but does not eliminate". With three constant biases in the
        model it eliminated the ordering spread exactly — 100%, to floating-point. Chasing
        that produced the real rule.

      


      
A content-free probe measures exactly one thing: the bias a content-free input
      exhibits. Any bias that is an additive constant in logit space shows up in full at
      the probe, so dividing it out is not an approximation — it is exact.


      
A second attempt made the bias stronger on ambiguous inputs, expecting a residual.
      That failed too, and more sharply: "N/A" is the most ambiguous input there is, so the probe
      saw that term at full strength and removed it as well.


      
What survives is only bias that needs content to exist. On this page that
      is a product term — the last exemplar changes how strongly the input's own evidence is read.
      At the probe it contributes exactly zero, so calibration cannot see it, and it stays
      order-dependent. Turn its slider to zero and the residual goes to zero with it.


      
So the honest advice is not "calibrate and stop worrying", and it is not "calibration only
      helps a bit" either. It is: calibration removes constant bias completely and
      interaction bias not at all. Balance the labels, calibrate, and then still evaluate
      more than one ordering — because you only get to ship one order, and the part calibration
      cannot reach is the part that depends on your actual inputs.

🔨 How it is built


      
1. The biases are declared, not discovered

      
function score(prompt, x, cfg){
  let s = cfg.signal * x.polarity;                       // the actual content

  prompt.forEach((ex, i) => {
    const recency = Math.pow(cfg.recencyDecay, prompt.length - 1 - i);
    s += cfg.recency * recency * ex.polarity;            // nearest example weighs most
  });

  const maj = prompt.reduce((a, e) => a + Math.sign(e.polarity), 0) / prompt.length;
  s += cfg.majority * maj;                               // unbalanced set pulls
  s += cfg.commonToken;                                  // one label is simply likelier

  return s;
}

      
This is a stand-in, and the page says so on the tin. Simulating an LLM would be
      dishonest; simulating three published, named biases with the coefficients on screen is a
      model of the mechanism — you can set any of them to zero and watch the corresponding effect
      vanish, which is the only claim being made.


      
2. Permutations, generated properly

      
function* permutations(arr){
  if (arr.length <= 1) { yield arr; return; }
  for (let i = 0; i < arr.length; i++){
    const rest = arr.slice(0, i).concat(arr.slice(i + 1));
    for (const p of permutations(rest)) yield [arr[i]].concat(p);
  }
}

      
A generator, so 720 orderings never all exist at once. The test asserts
      count === 720 and that all 720 are distinct — the second one catches the
      classic swap-in-place bug that produces the right count with duplicates in it.


      
3. Calibration is a division, and the identity check matters

      
function calibrate(prompt, cfg){
  const cf = probabilities(prompt, CONTENT_FREE, cfg);   // "N/A" - nothing to classify
  return { w: [1 / cf[0], 1 / cf[1]] };
}

function predictCalibrated(prompt, x, cal, cfg){
  const p = probabilities(prompt, x, cfg);
  const raw = [p[0] * cal.w[0], p[1] * cal.w[1]];
  const z = raw[0] + raw[1];
  return [raw[0] / z, raw[1] / z];                       // renormalise
}

      
The renormalisation is not cosmetic — without it the weighted values are not a
      distribution, and every downstream threshold is meaningless. The test asserts that a prompt
      with no bias at all calibrates to a no-op, which is the property that proves
      the correction is not just adding a second bias on top of the first.


      
4. Slot influence is an ablation, not a theory

      
for (let i = 0; i < prompt.length; i++){
  const flipped = prompt.map((e, j) => j === i ? { ...e, polarity: -e.polarity } : e);
  influence[i] = mean(|predict(prompt, x) − predict(flipped, x)| over the test set);
}

      
Flip the label at one position, measure how far every prediction moved. No claims about
      attention, no interpretability story — a controlled intervention and a number. The recency
      curve falls out of it rather than being asserted.


      
5. What the tests pin

      
// the mechanism is real and separable
assert(spreadWith(recency=0)  < spreadWith(recency=0.55));
assert(spreadWith(majority=0) < spreadWith(majority=0.60));

// calibration helps but does NOT eliminate
assert(spreadCalibrated < spreadUncalibrated);
assert(spreadCalibrated > 0);            // the honest half

// and it is a no-op on an unbiased prompt
assert(|calibrated − uncalibrated| < 1e-12) when all biases are 0;

      
That third assertion is the one worth copying. A correction that improves the metric on
      biased input and also changes unbiased input is not a correction — it is a second
      bias that happens to point the other way.
