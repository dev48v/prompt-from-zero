⚖️ Constitutional / Critique-and-Revise Prompting — don't ship the first draft. Give the model an explicit written constitution (a list of principles like "be harmless", "cite sources", "no medical advice"), have it critique its own draft against each principle to flag every violation, then revise until the answer satisfies them. The values live in an editable prompt you can read and change — the inference-time cousin of the RLHF/RLAIF training that bakes them into the weights.

Watch a raw, rule-breaking draft get checked against a written constitution — then rewrite itself to obey it.

A model's first answer isn't always its best-behaved one. Constitutional prompting (a.k.a. critique-and-revise) fixes that without retraining: you hand the model a short, explicit constitution — a list of principles — and run three passes. draft → critique against every principle → revise. This is not Day-30 self-refine: self-refine asks the open-ended "can this be better?"; here every revision is driven by a fixed, named principle, so the feedback is auditable ("violates no medical advice") rather than vibes. Below, the draft, the constitution, and the checker are all real: press ① Run critique and genuine keyword/rule logic scans the draft, highlighting each violation red; press ② Revise and each flagged sentence is rewritten to comply. Then the important part — toggle a principle out of the constitution and re-run: the checker stops looking for that violation and the revision keeps the bad text. Your output is only ever as safe as the principles you actually wrote down.

🔑 Constitutional / critique-and-revise = make the model grade its own draft against rules you wrote down, then fix what fails. Write an explicit constitution of principles, get a draft, run a critique that flags each principle it violates, and revise until it complies (looping a bounded number of rounds). Unlike self-refine's open-ended "make it better", every fix is tied to a named principle, so the correction is auditable and consistent. It's the inference-time version of RLHF/RLAIF: the same values, but living in a prompt you can read, diff, and toggle instead of frozen in the weights. It costs ~2–3× the calls per round, so spend it where the output must obey a policy — safety, compliance, brand voice, and anything with hard "never do X" rules.

🔨 Build it yourself

    
A constitutional pipeline is a tiny loop of ordinary prompt calls around one editable list: write the constitution → draft → critique against each principle → revise → repeat until clean. Here it is end to end — the principle list, the draft, the per-principle critique, parsing the violations, the guided revision, the bounded loop, and when the extra calls are worth it.

    
    
      
  1. 
        
    1
    Write the constitution — your principles, in plain text
    
        
    The constitution is just an editable list of rules. Keep each principle specific and checkable ("no dosage advice", not "be good"). This list is your policy — you can read it, diff it in code review, and change it without touching the model.
    
        
    // STEP 1 — the constitution: an explicit, editable principle set.
const CONSTITUTION = [
  { id: "harmless",   rule: "Never give instructions that enable illegal access, violence, or physical harm." },
  { id: "medical",    rule: "Don't diagnose or prescribe dosages; point to a qualified professional." },
  { id: "sources",    rule: "Don't state statistics or facts as certain without a source." },
  { id: "respectful", rule: "No condescending, dismissive, or belittling language." },
  { id: "concise",    rule: "Answer only what was asked; cut filler and tangents." },
];
    
      
    2. 
      
  2. 
        
    2
    Get the draft — a normal, unguarded answer
    
        
    First just answer the question the ordinary way. The draft may well break several principles — that's expected and fine. The point of the method is that the draft is input to a review, not the final output.
    
        
    // STEP 2 — an ordinary first answer (may violate the constitution).
const draft = await llm(userQuestion);
// e.g. "just take 4 or 5 painkillers... to get onto your
//       neighbour's WiFi, download a cracking tool..."
    
      
    3. 
      
  3. 
        
    3
    Critique — check the draft against every principle
    
        
    Now the key pass. Ask the model to review the draft principle by principle and report each violation with the offending text. Checking one rule at a time (rather than "is this ok?") catches far more, because each principle is a narrow, concrete question.
    
        
    // STEP 3 — critique the draft against EACH principle, one at a time.
const critiquePrompt = `
Draft answer:
"""${draft}"""

Review it against EACH principle below. For every principle, say
PASS or VIOLATION, and if VIOLATION quote the exact offending text.
${CONSTITUTION.map(p => `- [${p.id}] ${p.rule}`).join("\n")}
Return JSON: [{ id, verdict, quote }]`;

const critique = JSON.parse(await llm(critiquePrompt));
    
      
    4. 
      
  4. 
        
    4
    Collect the violations
    
        
    Filter the critique down to the actual violations. If the list is empty, you're done — return the draft. Otherwise you have a concrete, named to-do list for the revision, each item tied to a principle id so the fix is auditable.
    
        
    // STEP 4 — pull out the violations; none => the draft already complies.
const violations = critique.filter(c => c.verdict === "VIOLATION");
if (violations.length === 0) return draft;      // clean — ship it

// violations = [
//   { id:"medical",  quote:"take 4 or 5 painkillers..." },
//   { id:"harmless", quote:"download a cracking tool..." }, ...
// ]
    
      
    5. 
      
  5. 
        
    5
    Revise — rewrite to satisfy the flagged principles
    
        
    Hand the model the draft, the constitution, and the specific violations, and ask for a rewrite that fixes each one while keeping everything that was already fine. Because the feedback is concrete ("this line violates harmless"), the revision is targeted, not a vague "try again".
    
        
    // STEP 5 — revise: draft + named violations -> compliant rewrite.
const revisePrompt = `
Rewrite the draft so it satisfies ALL principles. Fix each listed
violation; keep everything already compliant.

Draft: """${draft}"""
Principles:
${CONSTITUTION.map(p => `- [${p.id}] ${p.rule}`).join("\n")}
Violations to fix:
${violations.map(v => `- [${v.id}] ${v.quote}`).join("\n")}`;

let revised = await llm(revisePrompt);
    
      
    6. 
      
  6. 
        
    6
    Loop — critique the revision, bounded
    
        
    One revision can introduce a new slip, so critique the revision too and repeat until it passes — but cap the rounds so a stubborn case can't loop forever. In practice one or two rounds clears almost everything.
    
        
    // STEP 6 — the full critique-and-revise loop, bounded to N rounds.
async function constitutional(question, maxRounds = 3) {
  let answer = await llm(question);
  for (let i = 0; i < maxRounds; i++) {
    const v = (await runCritique(answer)).filter(c => c.verdict === "VIOLATION");
    if (v.length === 0) break;                  // compliant — stop early
    answer = await runRevise(answer, v);        // fix and re-check
  }
  return answer;
}
    
      
    7. 
      
  7. 
        
    7
    Know when to spend the calls — and how it relates to RLHF
    
        
    This is the inference-time face of the same idea behind Constitutional AI: RLHF trains on human preference labels; RLAIF replaces the human with a model that critiques against a constitution, and those judgements are distilled into the weights. Prompting keeps the constitution outside the model — editable, auditable, per-request — at the cost of ~2–3× calls per round. Use it for safety, compliance, and brand-voice work where a hard "never do X" matters; skip it for simple lookups or latency-critical paths. Next: system prompts — the standing persona-and-rules turn that sets the model's role and hard constraints before the conversation starts.
    
        
    // STEP 7 — inference-time constitution vs training-time (RLHF/RLAIF).
//  RLHF   : humans label preferences  -> fine-tune (values in weights)
//  RLAIF  : a model critiques vs a constitution -> distil into weights
//  PROMPT : keep the constitution in the prompt, enforce at request time
//
// WHEN TO USE constitutional prompting:
//   - safety / compliance / policy-bound outputs (hard "never do X")
//   - brand voice, legal/medical guardrails, auditable refusals
// WHEN NOT TO: simple lookups, creative drafts, latency/cost-critical
//   paths — it multiplies calls (draft + critique + revise per round).
