PromptFromZero · Day 56

🔬 Cognitive Verifier — a prompt pattern from White et al.'s Prompt Pattern Catalog that stops the model from firing a shallow, one-shot answer at a big, open question. Instead of answering the question you asked, the model first generates a handful of sub-questions whose answers it would need to answer well, answers each one independently, and only then combines those sub-answers into a single, better-reasoned final answer. It's a decomposition pattern with a precise two-part skeleton, expressed as (P) contextual statements: “when asked a question, generate additional questions that would help answer it more accurately” and “combine the answers to those questions to produce the overall answer.” The payoff is twofold — accuracy goes up because the model is forced to cover the sub-issues a snap answer skips, and the reasoning becomes legible: you can read the scaffolding (each sub-question and its answer) and check the work instead of trusting a single confident paragraph. It shines on broad, under-specified questions — “is this startup idea viable?”, “what killed the dinosaurs?”, “should I index this column?” — where the hard part is knowing which questions to ask. This page is genuinely interactive with no API and no network: a self-contained, deterministic verifier decomposes a canned high-level question into 3–5 sub-questions, reveals each sub-answer, then synthesizes the combined answer — shown side by side against the shallow one-shot answer so you can watch the gap. Distinct from Day 55 (Flipped Interaction — the model asks you questions to gather requirements); here the model asks itself questions and answers them to reason better.

🅑 Cognitive verifier — decompose → answer → combine
🔑 The Cognitive Verifier turns one hard question into several easy ones, then reassembles the answer. A single-pass answer to a broad question is capped by whatever the model happens to surface in one go — so it reaches for the headline and quietly skips the sub-issues that actually decide the answer (who pays? how selective is the column? what was the mechanism?). The pattern forces coverage: it makes the model first enumerate the sub-questions a good answer depends on, answer each in isolation where it's far less likely to slip, and only then combine those grounded sub-answers into the final response. That buys two things at once — accuracy, because each sub-answer is a smaller, more tractable problem than the whole, and legibility, because the scaffolding is right there to inspect: you can see which questions it asked, check each answer, and catch a wrong step instead of trusting one confident paragraph. The whole pattern is two (P) contextual statements — generate the sub-questions, then combine their answers — and it's the go-to move whenever the hard part of a question is knowing what to ask.

🔨 Build it yourself

    
Cognitive Verifier is a prompt pattern, not a model feature — you assemble it from two (P) contextual statements (generate sub-questions, then combine their answers). You can run it as a single self-contained prompt, or — for control, parallelism and inspectable intermediates — orchestrate it as three explicit stages. Here it is both ways, provider-portable (Vercel AI SDK's system + messages, which map to Anthropic and OpenAI alike), with the same decompose → answer → combine flow the demo above runs and a copy-paste template.

    1
    The idea in one line — don't answer, first ask what you'd need to know
    
        
    A one-shot answer to a broad question is only as good as whatever the model surfaces in a single pass — so it grabs the headline and skips the sub-issues. The Cognitive Verifier inserts a beat: generate the sub-questions a good answer depends on, answer each, then combine. The reasoning becomes both more accurate and inspectable.
    
        
    // One-shot  →  capped by one pass, skips the sub-issues:
//   Q: "Is this startup idea viable?"
//   A: "Sure, sounds great — go for it!"   (no market / cost / moat)
//
// Cognitive verifier  →  decompose, answer, combine:
//   1) Who pays, and how many are there?
//   2) Willingness to pay vs free alternatives?
//   3) Cost to build & run?   4) What's the moat?
//   → combine the four answers → a reasoned verdict.

    The pattern skeleton — the two (P) contextual statements
    
        
    White et al.'s catalog describes each pattern as a set of fundamental (P) contextual statements. Cognitive Verifier needs just two: generate the sub-questions that would help answer more accurately, and combine their answers into the overall answer. Get those two right and the decompose-then-recombine behaviour is reliable.
    
        
    // STEP 2 — the (P) contextual statements of the Cognitive Verifier.
// (P1) generate sub-questions:
//   "When you are asked a question, generate a number of additional
//    questions that would help answer it more accurately."
// (P2) combine the answers:
//   "Combine the answers to the individual questions to produce
//    the final answer to the overall question."
//
// Optional (P3): bound the count (3-5) and answer each independently.

    3
    The single-prompt version — the trigger
    
        
    The simplest deployment is one system instruction that encodes both statements and pins a parseable shape. The model does all three moves in one turn: it lists the sub-questions with answers, then a combined final answer. Cheap, one call, and the scaffolding is visible in the output.
    
        
    // STEP 3 — encode the pattern as a reusable system prompt.
const VERIFIER_SYSTEM =
  "When I ask a question, do NOT answer it directly first. " +
  "Generate 3-5 additional sub-questions whose answers would help " +
  "you answer my question more accurately and completely. Answer " +
  "each sub-question independently and concisely. THEN combine " +
  "those answers into a single, well-reasoned final answer, noting " +
  "any caveats the sub-answers surfaced. Format:\n" +
  "Sub-questions:\n1. <q> — <answer>\n...\nFinal answer: <combined>";

    4
    Stage 1 — generate the sub-questions (decompose)
    
        
    For control, parallelism and inspectable intermediates, orchestrate it as three explicit stages instead of one prompt. Stage 1 asks only for the sub-questions as structured data — nothing else — so you can render them, cap the count, and fan the next stage out. This is the exact decomposition the demo's step ① performs.
    
        
    // STEP 4 — stage 1: decompose into sub-questions (JSON out).
import { generateText, generateObject } from "ai";
import { openai } from "@ai-sdk/openai";
import { z } from "zod";

async function decompose(question) {
  const { object } = await generateObject({
    model: openai("gpt-4o"),
    schema: z.object({ subQuestions: z.array(z.string()).min(3).max(5) }),
    prompt: `Question: ${question}\n\nList 3-5 sub-questions whose ` +
            `answers you would need to answer this well. Questions only.`,
  });
  return object.subQuestions;               // ["Who pays?", "Moat?", ...]
}
    
      
    5. 
      
  5. 
        
    5
    Stage 2 — answer each sub-question independently
    
        
    Answer every sub-question on its own. Because each is a smaller, better-scoped problem than the original, the model is far less likely to slip — and because the calls are independent, you can run them in parallel. Keep each answer with its question so the combine stage (and your UI) has the full scaffolding.
    
        
    // STEP 5 — stage 2: answer each sub-question in isolation (parallel).
async function answerEach(subQuestions) {
  return Promise.all(subQuestions.map(async (q) => {
    const r = await generateText({
      model: openai("gpt-4o"),
      prompt: `Answer concisely and factually: ${q}`,
    });
    return { q, a: r.text.trim() };          // keep q paired with its answer
  }));
}
// smaller scope per call → fewer slips than one giant answer.
    
      
    6. 
      
  6. 
        
    6
    Stage 3 — combine the sub-answers into the final answer
    
        
    The payoff turn. Feed the paired sub-questions and answers back in and ask for one combined answer to the original question, grounded in those sub-answers. This is (P2), and it's the demo's step ③ — the final response reflects every sub-answer instead of a single first-pass guess.
    
        
    // STEP 6 — stage 3: combine the grounded sub-answers.
async function combine(question, answered) {
  const notes = answered
    .map((x, i) => `${i + 1}. ${x.q}\n   ${x.a}`).join("\n");
  const r = await generateText({
    model: openai("gpt-4o"),
    prompt: `Original question: ${question}\n\n` +
            `Sub-questions & answers:\n${notes}\n\n` +
            `Using ONLY the reasoning above, give a single well-reasoned ` +
            `answer to the original question, noting any caveats.`,
  });
  return r.text.trim();
}

  7. 
        
    7
    Wire the three stages together — the verifier pipeline
    
        
    Chain the stages into one function that returns both the final answer and the scaffolding, so callers can render the sub-questions and audit the reasoning. This is precisely the decompose → answer → combine flow the demo drives — and returning the intermediates is what makes the reasoning legible.
    
        
    // STEP 7 — the full Cognitive-Verifier pipeline.
async function cognitiveVerifier(question) {
  const subQuestions = await decompose(question);      // ① generate
  const answered     = await answerEach(subQuestions); // ② answer each
  const finalAnswer  = await combine(question, answered); // ③ combine
  return { question, answered, finalAnswer };          // + scaffolding
}

    📋
    Copy-paste — the Cognitive-Verifier template (with the (P) statements)
    
        
    Drop this straight into your system field and add your question. The two (P) contextual statements are labelled so you can see the skeleton; capping the count and answering each independently is what keeps the decomposition useful.
    
        
    When I ask you a question, do not answer it directly. Instead:

(P1 · generate) First generate 3-5 additional sub-questions whose
answers would help you answer my question more accurately and
completely. Answer each sub-question independently and concisely —
do not let one answer contaminate another.

(P2 · combine) Then combine those answers into a single, well-reasoned
final answer to my original question. Note any caveats or
disagreements the sub-answers surfaced; do not paper over them.

Format:
Sub-questions & answers:
1. [sub-question] — [answer]
2. ...
Final answer: [combined answer to the original question]

My question: [YOUR QUESTION]

You learned the Cognitive Verifier: instead of firing a one-shot answer at a broad question, the model first generates the sub-questions a good answer depends on, answers each independently, then combines those sub-answers into a single better-reasoned response. It's two (P) contextual statements — generate, then combine — and it buys accuracy (each sub-answer is a smaller, more tractable problem) plus legibility (the scaffolding is right there to inspect). You can ship it as one self-contained prompt or orchestrate it as three explicit stages (decompose → answer each → combine) when you want parallelism and inspectable intermediates. Reach for it on open, under-specified questions where the hard part is knowing what to ask — viability calls, research questions, engineering decisions, diagnosis. It's a cousin of least-to-most (D18, dependent sub-problems solved in order) and self-ask (D19, follow-ups for multi-hop lookups); the Cognitive Verifier's sub-questions are independent coverage checks folded back together.
