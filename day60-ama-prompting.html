PromptFromZero · Day 60

❓ AMA Prompting (“Ask Me Anything”) — there is no one perfect prompt, so stop hunting for it. AMA (Arora et al., 2022) asks the same question through many different prompt formats — open-ended question-answering, cloze, question-generation, a paraphrase, a few-shot variant — collects one noisy vote from each, and then combines them with weak supervision rather than a plain majority. The combiner is the interesting half: it looks only at how often the prompts agree with each other, uses that to estimate each prompt's accuracy without ever seeing a label, and turns those estimates into log-odds weights so a confidently-wrong prompt gets a negative weight instead of an equal vote. Two things it is not: it is not Day 3 self-consistency (that is ONE prompt sampled k times, then majority vote — it fixes sampling noise but cannot fix the prompt's own bias), and it is not an eval. Everything below runs live in your browser on a baked 40-item benchmark: the model calls are simulated by seeded, deterministic noisy labelers, but every number on screen — agreement rates, triplet-method accuracy estimates, weights, the aggregated prediction and all three scores — is computed at runtime, in front of you.

One prompt is a guess. Many prompts plus weak supervision is an estimate.

40 baked reviews, gold labels known to us but never to the aggregator. Seven prompt views of the same task, each a genuinely different format with its own error profile. Toggle views, break conditional independence, re-seed — every number recomputes.

🤝 Pairwise agreement — the only signal the aggregator gets

Each cell is how often two views output the same label. Two views agree either when both are right or when both are wrong — so agreement carries accuracy information even with no gold anywhere in sight. The method-of-moments identity is E[λiλj] = ai·aj, where a = 2·accuracy − 1 and E[λiλj] = 2·agreement − 1.

📐 Triplet estimates → log-odds weights
🔁 Day 3 self-consistency vs Day 60 AMA — same budget of k calls, spent two different ways
Self-consistency samples ONE prompt k times. It averages away sampling noise, so it climbs fast and then flattens at that prompt's own ceiling — the questions this prompt reads wrongly, it reads wrongly on every sample. AMA spends the same k calls on different prompts, whose hard questions are not the same questions, so the errors actually cancel instead of stacking. They compose, too: sample each view a few times, then aggregate the per-view majorities.
🔑 The aggregator never sees a label — that is the whole point. Press 👁 Gold column and hide it: nothing on this page changes except the colours, because aggregate(L) takes the label matrix and nothing else. It computes agreement rates, recovers each view's accuracy from triplets of agreements, converts those to w = log(a/(1−a)), and takes sign(Σ wiλi). Notice what happens to the leading yes-question: it agrees with everyone far less than chance, so its estimated accuracy lands below 0.5, its weight goes negative, and the aggregate starts reading it backwards — a confidently-wrong prompt turned into a useful one, with no labels. Plain majority vote cannot do that; it hands the same vote to the best prompt and the worst.

AMA = many prompt formats, one vote each, then weak supervision learns whom to trust from agreement alone. Self-consistency = one prompt, k samples, majority vote.

🔨 Build it yourself

    
AMA is two pieces that people usually get in the wrong proportion. The first is easy and everyone does it: write several prompts instead of one. The second is where the win actually lives: a combiner that learns whom to trust from agreement alone, so you are not stuck giving your worst prompt the same vote as your best. Below is exactly what this page runs — the views, the label matrix, the agreement moments, the triplet estimator, the log-odds vote — followed by the guards and the budget maths you need before shipping it.

    
    

      
  1. 
        
    1
    Define the task as a binary decision the votes can be cast on
    
        
    Weak supervision needs a fixed label space to vote over. Start binary — sentiment, entailment, “is this claim supported?”, “does this ticket need escalation?” — and map every view's free-text output down to +1 / −1. Multi-class works too (one-vs-rest, or a categorical model) but the maths is cleanest and the debugging is honest when there are two options.
    
        
    // STEP 1 — the benchmark. Gold labels exist for MEASUREMENT only;
// the aggregator below never receives them.
const ITEMS = [
  { t: "Battery lasts two full days - I stopped carrying the charger.", y:  1 },
  { t: "Died on day nine. Refund is still 'processing'.",              y: -1 },
  // ... 40 items, 20 positive / 20 negative
];
const GOLD = ITEMS.map(it => it.y);          // +1 / -1

  2. 
        
    2
    Write k diverse prompt views — different formats, not reworded synonyms
    
        
    A view is a full strategy for extracting the answer, not a rephrasing. The AMA paper's headline empirical finding is that open-ended question-answering beats restrictive yes/no, so bias your set toward formats that let the model produce natural text and then map that text to a label. Diversity of format is what makes the errors different, and different errors are the only thing aggregation can exploit.
    
        
    // STEP 2 — seven views, seven different SHAPES of the same question.
const VIEWS = [
  { id:"oqa",   name:"Open-ended QA",        // strongest: free text, then map
    prompt:'Review: "{t}"\nQuestion: What is the author’s opinion of the product?\nAnswer:' },
  { id:"qgen",  name:"Question-gen -> answer",
    prompt:'Write a question that settles the sentiment, then answer it.\nQ: Would the reviewer buy this again?\nReview: "{t}"\nA:' },
  { id:"few",   name:"Few-shot",
    prompt:'"Charges fast, holds all day." -> positive\n"Stopped working after two weeks." -> negative\n"{t}" ->' },
  { id:"cloze", name:"Cloze",
    prompt:'"{t}"\nOverall, the reviewer sounds ____ about the product.' },
  { id:"para",  name:"Paraphrased instruction",
    prompt:'Read the note and tell me, in your own words, whether the\nperson writing it ended up happy.\nNote: "{t}"' },
  { id:"yn",    name:"Restrictive yes/no",   // the format AMA says underperforms
    prompt:'Review: "{t}"\nIs this review positive? Answer Yes or No.' },
  { id:"lead",  name:"Leading yes-question", // deliberately biased
    prompt:'Review: "{t}"\nThis is a happy customer, right? Yes or No.' },
];
    
      
    3. 

      
  3. 
        
    3
    Collect the label matrix L — n items × k views
    
        
    Run every view over every item and store one ±1 per cell. Map free text to a label with a tiny deterministic mapper and count anything unmappable as an abstention (0) rather than a guess. This matrix is the whole input to everything that follows — no prompts, no text, no labels.
    
        
    // STEP 3 — in production this is k API calls per item, cached by (view, item).
async function labelMatrix(items, views){
  return Promise.all(views.map(v =>
    Promise.all(items.map(async it => {
      const text = await call(v.prompt.replace("{t}", it.t));
      return toLabel(text);                 // "sounds delighted" -> +1
    }))
  ));
}
// tiny, auditable mapper - keep it boring and log every miss.
const POS = /\b(positive|happy|delighted|pleased|good|great|yes|would)\b/i;
const NEG = /\b(negative|unhappy|disappointed|bad|poor|no|wouldn.t)\b/i;
function toLabel(s){ if (POS.test(s) && !NEG.test(s)) return 1;
                     if (NEG.test(s)) return -1; return 0; }   // 0 = abstain
    
      
    4. 

      
  4. 
        
    4
    Baseline first — plain majority vote
    
        
    Always compute this. It is three lines, it is often good, and it is the number weak supervision has to beat to justify itself. It is also the thing with the clean failure mode: every view gets one vote regardless of quality, so one confidently-wrong prompt with a class bias drags the whole ensemble toward its bias.
    
        
    // STEP 4 — majority vote. Ties resolve to +1, deterministically.
function majorityVote(L){
  const n = L[0].length, out = new Array(n);
  for (let q = 0; q < n; q++){
    let s = 0;
    for (let i = 0; i < L.length; i++) s += L[i][q];
    out[q] = (s > 0) ? 1 : ((s < 0) ? -1 : 1);
  }
  return out;
}
// An even k plus a tie rule is a silent coin-flip. Prefer odd k, or make
// the tie rule an explicit product decision (here: +1, and documented).
    
      
    5. 

      
  5. 
        
    5
    Agreement rates — the unlabeled signal
    
        
    Take every pair of views and compute the mean of their product. For ±1 votes, E[λiλj] is just 2·(agreement rate) − 1: it is +1 when two views always agree, 0 when they are independent coin flips, negative when they systematically disagree. No labels are touched anywhere in this function.
    
        
    // STEP 5 — the second-moment matrix. Diagonal is always 1.
function pairwiseProducts(L){
  const k = L.length, n = L[0].length, E = [], A = [];
  for (let i = 0; i < k; i++){ E.push(new Array(k).fill(0)); A.push(new Array(k).fill(0)); }
  for (let i = 0; i < k; i++) for (let j = 0; j < k; j++){
    let s = 0;
    for (let q = 0; q < n; q++) s += L[i][q] * L[j][q];
    E[i][j] = s / n;             // E[lambda_i * lambda_j]
    A[i][j] = (s / n + 1) / 2;   // plain agreement rate, for humans
  }
  return { E: E, A: A };
}
    
      
    6. 

      
  6. 
        
    6
    The triplet method — recover each view's accuracy without labels
    
        
    Under conditional independence, E[λiλj] = aiaj where ai = E[λiy] = 2·accuracyi − 1. Three views give three equations in three unknowns, and the product/quotient falls out algebraically. The square root only gives magnitudes, so signs are resolved against a reference view and then oriented globally by assuming the majority of your prompts are better than random — still no labels.
    
        
    // STEP 6 — |a_i| = sqrt( E[ij] * E[ik] / E[jk] ), averaged over all triplets.
function tripletEstimate(E){
  const k = E.length, mag = new Array(k).fill(0);
  for (let i = 0; i < k; i++){
    const vals = [];
    for (let j = 0; j < k; j++){ if (j === i) continue;
      for (let l = j + 1; l < k; l++){ if (l === i) continue;
        if (Math.abs(E[j][l]) < 1e-6) continue;             // unusable triplet
        vals.push(clamp(Math.sqrt(Math.abs((E[i][j] * E[i][l]) / E[j][l])), 0, 0.99));
      }
    }
    mag[i] = vals.length ? mean(vals) : 0;
  }
  // sign vs a reference view, then a global orientation flip if needed
  let ref = 0, best = -1;
  for (let i = 0; i < k; i++){ let s = 0;
    for (let j = 0; j < k; j++) if (j !== i) s += Math.abs(E[i][j]);
    if (s > best){ best = s; ref = i; } }
  let mu = mag.map((m, i) => (i === ref || E[ref][i] >= 0) ? m : -m);
  let tot = 0; for (let i = 0; i < k; i++) tot += mu[i];
  if (tot < 0) mu = mu.map(x => -x);       // assume most prompts beat chance
  return { mu: mu, acc: mu.map(m => clamp((1 + m) / 2, 0.02, 0.98)), ref: ref };
}
    
      
    7. 

      
  7. 
        
    7
    Log-odds weights and the weighted vote
    
        
    Under conditional independence the optimal combination is a naive-Bayes vote, and its weight per labeler is exactly the log-odds of its accuracy. That is why w = log(a/(1−a)) and not w = a: a view at 0.50 gets weight 0, and a view below 0.50 gets a negative weight, which flips its vote instead of discarding it. Clamp the accuracy away from 0 and 1 or one view earns an infinite weight and becomes a dictator.
    
        
    // STEP 7 — the whole aggregator. Signature takes L. That is all it takes.
function logOddsWeights(acc){ return acc.map(a => Math.log(a / (1 - a))); }

function weightedVote(L, w){
  const n = L[0].length, out = new Array(n);
  for (let q = 0; q < n; q++){
    let s = 0;
    for (let i = 0; i < L.length; i++) s += w[i] * L[i][q];
    out[q] = (s > 0) ? 1 : ((s < 0) ? -1 : 1);   // same tie rule as majority
  }
  return out;
}

function aggregate(L){
  const pp = pairwiseProducts(L);
  const t  = tripletEstimate(pp.E);
  const w  = logOddsWeights(t.acc);
  return { E: pp.E, A: pp.A, mu: t.mu, acc: t.acc, w: w,
           pred: weightedVote(L, w), ref: t.ref };
}
// Equal accuracies -> equal weights -> weightedVote === majorityVote.
// Weak supervision can only ever help when the views DIFFER in quality.
    
      
    8. 

      
  8. 
        
    8
    Measure the lift — against the right baselines
    
        
    Score three things on a held-out labeled slice: the best single view, plain majority, and the AMA aggregate. Be honest that “best single view” is an oracle baseline — you can only know which view is best if you have labels, which is the situation AMA is designed to avoid. If AMA does not beat majority, your views are too similar or too uniformly good; both are diagnosable from the agreement matrix.
    
        
    // STEP 8 — the three numbers that decide whether this is worth k calls.
const acc = (p, g) => p.filter((x, i) => x === g[i]).length / g.length;

const perView  = L.map(col => acc(col, GOLD));
const best     = Math.max.apply(null, perView);   // ORACLE - needs labels
const majority = acc(majorityVote(L), GOLD);
const ama      = acc(aggregate(L).pred, GOLD);    // label-free at inference

console.log({ best, majority, ama, lift: ama - majority });
// Also print  estimated vs true accuracy per view: if the estimates are
// wildly off, conditional independence is broken (step 9), not the maths.
    
      
    9. 

      
  9. 
        
    9
    Guard the assumption — drop near-duplicate prompts
    
        
    Everything above rests on conditional independence: given the true label, the views' errors are unrelated. Two prompts that are paraphrases of each other break it — they agree because they are the same prompt, the estimator reads that agreement as competence, and both get inflated weights while a genuinely independent third view is under-weighted. Flip the 🔗 Correlated prompts toggle in LOOK and watch the estimates drift and the aggregate lose ground. The cheap guard is a duplicate filter on the agreement matrix itself.
    
        
    // STEP 9 — greedily drop views that agree with a kept view above a cap.
function dropDuplicates(L, ids, cap){
  const A = pairwiseProducts(L).A, keep = [];
  for (let i = 0; i < L.length; i++){
    const dup = keep.some(j => A[i][j] > (cap || 0.90));
    if (!dup) keep.push(i);
    else console.warn("dropping near-duplicate view: " + ids[i]);
  }
  return keep;
}
// Better still, model the correlation instead of pruning it: the structured
// weak-supervision literature (Snorkel / FlyingSquid) fits a dependency graph
// over the labelers. Pruning is the version you can ship this afternoon.

  10. 
        
    📋
    Cost, latency, and when NOT to reach for this
    
        
    AMA costs k× the calls and k× the tokens. It buys you accuracy from a small model without a fine-tune — that is the trade the paper makes, and it is a good one when your unit economics favour many cheap calls over one expensive one. Fan the k views out in parallel so latency is one call plus a rounding error, cache by (view, item), and stop before you build this if a single good prompt already clears your bar.
    
        
    # The decision table, in the order you should actually try things.

# 1. ONE good prompt              1x cost   - always try first, always.
# 2. Self-consistency (Day 3)     kx cost   - one prompt, k samples, majority.
#                                             Fixes SAMPLING noise only.
#                                             Needs temperature > 0.
# 3. AMA (today)                  kx cost   - k prompt FORMATS, weighted vote.
#                                             Fixes PROMPT bias too. Needs
#                                             genuinely different views.
# 4. AMA + self-consistency       k*m cost  - sample each view m times, take
#                                             the per-view majority, then
#                                             weak-supervise across views.
# 5. Fine-tune                    train $$  - once you have labels, or once
#                                             AMA has LABELLED a corpus for
#                                             you (its original purpose:
#                                             programmatic training data).

# Latency: fan out, do not loop.
results = await asyncio.gather(*[call(v.prompt.format(t=item)) for v in VIEWS])

🎉 Day 60 of PromptFromZero done.
You learned AMA prompting — “Ask Me Anything”, Arora et al. 2022 — which starts from an uncomfortable admission: there is no one perfect prompt, and prompt-to-prompt variance is enormous, so the search for the magic wording is a search for something that does not exist. AMA replaces it with two moves. First, ask the same question through many different prompt formats — and prefer open-ended question-answering over restrictive yes/no, which is the paper's headline empirical result, because a format that lets the model write natural text and then maps that text to a label beats one that forces a token the model rarely produces. Second, and this is the half that matters, combine the votes with weak supervision instead of a plain majority: compute how often the prompts agree with each other, use the identity E[λiλj] = aiaj and the triplet method to recover each prompt's accuracy with no labels at all, turn those into log-odds weights w = log(a/(1−a)), and take sign(Σ wiλi). That is what lets a confidently-wrong prompt earn a negative weight and get read backwards rather than dragging the vote. You saw all of it compute live on a 40-item benchmark: best single prompt, plain majority, and the AMA aggregate, with each view's estimated accuracy printed next to its true one so the estimator's work is visible. And you saw the honest limits — the whole thing rests on conditional independence, so near-duplicate prompts inflate their own estimates and degrade the result (flip the correlation toggle and watch it), and it costs k× the calls. Do not confuse it with Day 3 self-consistency: that is ONE prompt sampled k times and majority-voted, which averages away sampling noise but is capped by that prompt's own bias; AMA varies the prompt itself, and weights the results. 👉 Next up — LLM-as-judge: when the “right answer” is fuzzy (tone, helpfulness, faithfulness), grade outputs with a model against a rubric instead of an exact string.
