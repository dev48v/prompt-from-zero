PromptFromZero · Day 55

🔄 Flipped Interaction — a prompt pattern from White et al.'s Prompt Pattern Catalog that inverts who is driving the conversation. Normally you prompt the model: you carry the burden of knowing everything it needs and packing it into one message, and any gap you didn't think to mention is silently guessed. Flipped Interaction hands the model the wheel — you instruct it to ask you questions, one at a time, until it has gathered enough to accomplish a goal, and only then to produce the result. The pattern has a precise skeleton, expressed as (P) contextual statements: a role/goal (“ask me questions to achieve X”), a question cadence (“one at a time”), and a stop condition (“until you have enough to do X”). Under the hood it is slot-filling: the model keeps a mental checklist of the facts it still needs, asks the next missing one, and stops asking the moment the checklist is full. It shines wherever the human is the source of truth and doesn't know what's relevant up front — requirement gathering, onboarding wizards, intake forms, debugging interviews. This page is genuinely interactive with no API and no network: a self-contained, deterministic question-tree agent picks a goal (plan a trip · spec a schema · debug an error), asks you targeted questions one-by-one, tracks the slots live, and synthesizes a result only once every slot is filled. Distinct from Day 54 (Verbalized Confidence — making the model's uncertainty explicit); this is about making the model drive the requirement-gathering instead of you.

Pick a goal, then let the agent interview you — one question at a time — filling a slot checklist as you answer, and producing the result only once every slot is filled.

This is a real, interactive flipped-interaction session — but everything is deterministic (no API key, no network): the question tree, the slots and the synthesized output are all baked in, and the checklist, the progress bar and the stop condition are computed live from what you've answered. Notice the shape: the model asks, you answer — the reverse of normal prompting. Click an option to answer the current question; the agent immediately asks the next missing one and never jumps ahead. 🔑 Flipped Interaction moves the burden of knowing-what-to-ask from you to the model. In ordinary prompting you must anticipate everything the model needs and cram it into one message; whatever you forget, it quietly assumes — and a confident answer built on a wrong assumption is worse than no answer. Flipping the interaction turns that one-shot guess into a short interview: you tell the model its goal, that it should ask one question at a time, and when to stop, and it takes over the elicitation. Mechanically it's slot-filling — it keeps a running checklist of the facts it still needs, asks the next missing one, and only produces the deliverable once the checklist is complete, which is exactly the stop condition this demo enforces. That's why the pattern is a natural fit for requirement gathering, onboarding, intake and debugging interviews: the human is the source of truth but rarely knows up front which details matter, so letting the model pull them out one at a time yields a far more complete, grounded result than any single prompt could. The craft is in the three (P) contextual statements — role/goal, cadence, stop condition — plus giving it the slot list so it knows what “enough” means.

🔨 Build it yourself

    
Flipped Interaction is a prompt pattern, not a model feature — you assemble it from three (P) contextual statements (role/goal, cadence, stop condition) plus a slot list, then run it as a stateful, multi-turn loop instead of a single call. Here it is end to end, provider-portable (Vercel AI SDK's system + messages, which map to Anthropic and OpenAI alike), with the same slot-filling state machine the demo above runs and a copy-paste template.

    
    
      
  1. 
        
    1
    The idea in one line — flip who does the asking
    
        
    In normal prompting you ask and the model answers — so you carry the burden of knowing everything it needs. Flipped Interaction inverts that: you instruct the model to ask you questions until it has enough, then produce the result. The elicitation becomes the model's job, which is exactly what you want when the human is the source of truth but doesn't know what's relevant.
    
        
    // Normal prompting  →  you must know everything up front:
//   You:   "Plan me a 7-day mid-range beach trip for a
//           couple, relaxed pace."   (one dense message)
//   Model: <plan built on whatever you remembered to say>
//
// Flipped interaction  →  the model gathers it from you:
//   Model: "Where do you want to go?"      You: "Beach"
//   Model: "How long is the trip?"         You: "One week"
//   ...one question at a time... then → the plan.

    2
    The pattern skeleton — the three (P) contextual statements
    
        
    White et al.'s catalog describes each pattern as a set of fundamental (P) contextual statements. Flipped Interaction needs three: the role/goal (what it's interviewing you toward), the cadence (one question at a time), and the stop condition (when it has enough). Get those three right and the behaviour is reliable.
    
        
    // STEP 2 — the (P) contextual statements of Flipped Interaction.
// (P1) role + goal:
//   "I would like you to ask me questions to achieve GOAL."
// (P2) cadence:
//   "Ask me the questions one at a time and wait for my answer."
// (P3) stop condition:
//   "Keep asking until you have enough to GOAL, then produce OUTPUT."
//
// Optional (P4): scope the slots so 'enough' is unambiguous.
    
      
    3. 
      
  3. 
        
    3
    The system prompt — the trigger
    
        
    The whole behaviour lives in one system instruction that encodes the three statements and, crucially, names the slots so “enough” is concrete. Keep it in the system channel so the model stays in interviewer mode every turn instead of drifting back to answering.
    
        
    // STEP 3 — encode the pattern as a reusable system prompt.
const FLIPPED_SYSTEM =
  "You are gathering requirements to PLAN A TRIP. " +
  "Ask me questions ONE AT A TIME and wait for my answer before " +
  "asking the next. Do not make assumptions or answer for me. " +
  "You still need: destination type, trip length, budget, who is " +
  "travelling, and pace. Ask about the first thing you are still " +
  "missing. When you have ALL of them, stop asking and output the " +
  "final plan prefixed with 'PLAN:'. Ask your first question now.";

  4. 
        
    4
    Wire it up — a stateful, multi-turn loop
    
        
    Unlike a one-shot prompt, Flipped Interaction is a conversation: you keep appending the model's question and the user's answer to a growing messages array and call again. The loop runs until the model emits the finish marker instead of another question.
    
        
    // STEP 4 — drive the interview turn by turn.
import { generateText } from "ai";
import { openai } from "@ai-sdk/openai";

async function runFlipped(promptUser) {          // promptUser: ask the human
  const messages = [];
  while (true) {
    const r = await generateText({
      model: openai("gpt-4o"),
      system: FLIPPED_SYSTEM,
      messages,
    });
    messages.push({ role: "assistant", content: r.text });
    if (r.text.startsWith("PLAN:")) return r.text;   // stop condition met
    const answer = await promptUser(r.text);         // model asked → human answers
    messages.push({ role: "user", content: answer });
  }
}
    
      
    5. 
      
  5. 
        
    5
    Track the slots — the checklist of what it still needs
    
        
    “Enough” has to be defined. Model-side you name the slots in the prompt; but for a robust product you also track them in your own code so you control the flow, render a progress UI, and never depend on the model to remember. This is the exact state machine the demo runs: pick the next unfilled slot, ask it, record the answer.
    
        
    // STEP 5 — slot-filling state machine (deterministic, DOM-free).
const SLOTS = ["destination", "duration", "budget", "company", "pace"];

function nextSlot(filled) {                 // first slot not yet answered
  for (const s of SLOTS) if (!(s in filled)) return s;
  return null;                             // null → all filled
}
function isComplete(filled) { return nextSlot(filled) === null; }

// each turn: ask nextSlot(filled); on answer → filled[slot] = answer.
// the checklist IS the source of truth for what to ask next.
    
      
    6. 
      
  6. 
        
    6
    The stop condition — detect “enough”, then synthesize
    
        
    The stop condition is what keeps the pattern from either looping forever or firing early. When (and only when) every slot is filled do you switch the model out of interviewer mode and ask it to produce the deliverable from the collected answers. This is the guarantee the demo enforces: no complete checklist, no output.
    
        
    // STEP 6 — gate the synthesis on the stop condition.
async function step(filled, userAnswer, slot) {
  if (slot) filled[slot] = userAnswer;         // record the answer

  const missing = nextSlot(filled);
  if (missing) {
    return { kind: "ask", slot: missing };     // keep interviewing
  }
  // stop condition met → produce the result from filled slots
  const plan = await synthesize(filled);       // one final generation
  return { kind: "done", output: plan };
}
// can't reach "done" while nextSlot(filled) is non-null → no early finish.
    
      
    7. 
      
  7. 
        
    7
    Guard the edges — one at a time, no skipping, resumable
    
        
    Three failure modes to close off. Models love to batch questions — pin the cadence in the prompt and only render one at a time. They also skip ahead or re-ask — driving the flow from nextSlot() in your code prevents both. And because it's a conversation, persist filled so a dropped session resumes mid-interview instead of restarting.
    
        
    // STEP 7 — enforce order, and make sessions resumable.
function answer(filled, slot, value) {
  if (nextSlot(filled) !== slot) return filled;   // reject out-of-order
  return { ...filled, [slot]: value };            // only the current slot
}

// resumability: filled is plain data — save & reload it.
await store.put(sessionId, filled);               // persist after each turn
const filled = (await store.get(sessionId)) ?? {}; // resume where it left off

🎉 Day 55 of PromptFromZero done.
You learned Flipped Interaction: instead of prompting the model, you instruct it to ask you — one question at a time — until it has gathered enough to hit a goal, then produce the result. The pattern is three (P) contextual statements (role/goal, cadence, stop condition) over a slot-filling state machine: keep a checklist of what's still missing, ask the next gap, and synthesize only when the checklist is full — the stop condition that stops it looping forever and stops it finishing early. It runs as a stateful multi-turn loop (not a single call), and driving the order from your own nextSlot() keeps it one-at-a-time, skip-proof and resumable. It's the go-to pattern when the human is the source of truth but doesn't know what's relevant up front — requirement gathering, onboarding, intake, debugging interviews.
