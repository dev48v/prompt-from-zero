PromptFromZero · Day 52

✂️ Context management — fitting an ever-growing conversation into the model's fixed context window. Every turn you add (a user question + the assistant's reply) piles more tokens onto the system prompt and the whole history; once the running total crosses the window limit the request is rejected or silently truncated — so you must MANAGE the context: decide which turns to keep verbatim, which to drop, and which to compress. The core strategies are truncate-oldest (FIFO-drop the front until it fits), sliding-window (always keep just the last N turns), summarize-old (fold older turns into a compact running summary, keep the recent ones verbatim), and pinned + recent (never drop the system prompt and flagged key facts, then fill the remaining budget with the newest turns) — all governed by token-budgeting: count tokens per turn and keep the total under the limit. The tradeoff is the whole game: drop or over-compress and you lose the detail the model needs to stay coherent; keep everything and you blow the budget. Distinct from the system-prompt day (WHAT you pin) and from prompt/semantic caching (reuse for cost) — this is choosing what survives so the conversation still fits.

The window is a hard token budget. As you add turns the raw total climbs until it blows the budget. Each strategy manages it differently: truncate FIFO-drops the oldest turns (even the system prompt), sliding-window keeps a fixed last-N, summarize-old folds the early turns into one compact summary, and pinned + recent protects the system prompt and any 📌 turns then fills the rest with the newest. Everything below is deterministic (no API key): token counts, the trim decision and the summary are all computed live from the turns and the budget, so every toggle is felt immediately — including whether the model can still answer the final “remind me what stack we chose” question.

🔑 Context management is choosing what survives the window. The context window is a fixed token budget, and a chat only grows — so left alone, every conversation eventually overflows and the request fails or gets silently cut. Management is the answer: token-budget the history, then apply a strategy. Truncate-oldest is simplest but blunt — FIFO can drop the system prompt or the one early turn that held your requirements. Sliding-window keeps a fixed last-N: predictable, but count-based not token-based, so a big recent turn can still overflow and a tiny history wastes budget. Summarize-old compresses the early turns into a running summary — it preserves the gist of everything within a tiny token cost, at the price of verbatim detail. Pinned + recent is the workhorse: never drop the system prompt and flagged key facts, then fill the rest with the newest turns. The demo makes the tradeoff bite — with a tight budget, truncate and sliding-window forget the stack chosen in turn 1, so the final “remind me” question can't be answered; summarize and pinning keep it. In practice you combine them: pin the system prompt, summarize the middle, keep a recent window, all under a token budget. 🔨 Build it yourself

    
Context management is a function that runs before every request: count tokens → pin system → decide keep / drop / summarize → assemble under budget. Here it is end to end, provider-portable — real token counting with js-tiktoken, the four trimming strategies, and a combined manageContext() you reuse on every turn (works with the Vercel AI SDK's messages array, which maps to Anthropic and OpenAI alike).

    
    
      
  1. 
        
    1
    Count tokens — you can't budget what you can't measure
    
        
    Tokens, not characters, fill the window. Use the real tokenizer (js-tiktoken / tiktoken) so your count matches the model's; a rough chars/4 fallback is fine for a first pass but undercounts code and non-English. Count every message plus a small per-message overhead.
    
        
    // STEP 1 — measure tokens per message with a real tokenizer.
import { getEncoding } from "js-tiktoken";
const enc = getEncoding("cl100k_base");            // GPT-4o / 3.5 family

const countText = (s) => enc.encode(s).length;
const countMsg  = (m) => countText(m.content) + 4; // ~4 tok/message overhead
const countAll  = (msgs) => msgs.reduce((n, m) => n + countMsg(m), 0);

// no tokenizer handy? approximate — undercounts, so keep headroom:
const approx = (s) => Math.ceil(s.length / 4);

  2. 
        
    2
    Set the budget — leave room for the reply
    
        
    The window holds input + output. Budget the history to contextWindow − reserveForReply − systemTokens so you never crowd out the model's answer. The system prompt is spent first and always; everything else competes for what's left.
    
        
    // STEP 2 — the history budget is what's LEFT after system + reply.
const CONTEXT_WINDOW = 8192;   // model limit (input + output)
const RESERVE_REPLY  = 1024;   // keep room for the completion

function historyBudget(system) {
  return CONTEXT_WINDOW - RESERVE_REPLY - countMsg(system);
}
    
      
    3. 
      
  3. 
        
    3
    Truncate oldest — keep the newest that fit
    
        
    The simplest trimmer: walk the history from newest to oldest, keep messages while they fit the budget, drop the rest. It's FIFO on the front — cheap and stateless, but blunt: it will happily drop the early turn that held your requirements. Always keep the system prompt outside this loop.
    
        
    // STEP 3 — fit-from-newest: keep recent messages until the budget runs out.
function truncateOldest(history, budget) {
  const kept = [];
  let used = 0;
  for (let i = history.length - 1; i >= 0; i--) {   // newest → oldest
    const t = countMsg(history[i]);
    if (used + t > budget) break;                   // older ones are dropped
    kept.unshift(history[i]);
    used += t;
  }
  return kept;
}
    
      
    4. 
      
  4. 
        
    4
    Sliding window — a fixed last-N
    
        
    Keep exactly the last N turns regardless of size. Predictable and dead simple, but count-based, not token-based: a couple of long recent turns can still overflow, and a short history wastes budget. Good default when turns are roughly uniform; pair it with a token check as a guard.
    
        
    // STEP 4 — keep the last N messages (a fixed-size window).
function slidingWindow(history, n) {
  return history.slice(-n);
}
// guard: if the window still overflows, fall back to truncateOldest.
function windowThenFit(history, n, budget) {
  const win = slidingWindow(history, n);
  return countAll(win) <= budget ? win : truncateOldest(win, budget);
}
    
      
    5. 
      
  5. 
        
    5
    Summarize old — compress the middle
    
        
    Keep the last K turns verbatim; fold everything older into one running summary message with a cheap model. This preserves the gist of the whole conversation for a tiny token cost — the key move when early context matters but you can't afford it verbatim. Re-summarize incrementally as the tail grows so cost stays flat.
    
        
    // STEP 5 — summarize the older block, keep the recent tail verbatim.
async function summarizeOld(history, keepLast, summarize) {
  if (history.length <= keepLast) return history;
  const older  = history.slice(0, -keepLast);
  const recent = history.slice(-keepLast);
  const gist = await summarize(older);   // cheap model → 2–3 sentences
  const summaryMsg = {
    role: "system",
    content: "Summary of earlier conversation:\n" + gist,
  };
  return [summaryMsg, ...recent];        // 1 small msg replaces many
}
    
      
    6. 
      
  6. 
        
    6
    Pinned + recent — protect what must not be lost
    
        
    Reserve budget for pinned messages (the system prompt and any flagged key facts) first, then fill the remainder with the newest turns. Pins never get dropped, so the requirement stated in turn 1 survives no matter how long the chat runs — the fix for truncate's biggest failure mode.
    
        
    // STEP 6 — pinned messages are reserved; recent fills what's left.
function pinnedPlusRecent(history, budget, isPinned) {
  const pinned = history.filter(isPinned);
  const rest   = history.filter((m) => !isPinned(m));
  let used = countAll(pinned);           // pins are paid for up front
  const recent = [];
  for (let i = rest.length - 1; i >= 0; i--) {
    const t = countMsg(rest[i]);
    if (used + t > budget) break;
    recent.unshift(rest[i]);
    used += t;
  }
  // re-interleave pinned + recent back into chronological order:
  return history.filter((m) => pinned.includes(m) || recent.includes(m));
}

  7. 
        
    7
    Put it together — pin, summarize, window, under budget
    
        
    Production context management combines the moves: pin the system prompt, summarize the old middle, keep a recent window, and verify the whole thing fits before sending — every turn. Run it in front of your model call and reuse it across the conversation. It differs from the system prompt (D51 — the standing behaviour you pin) and from prompt/semantic caching (reuse for cost). Next: evaluation — regression-testing your outputs with promptfoo so a context change can't silently break quality.
    
        
    // STEP 7 — the combined manager, run before every model call.
async function manageContext(system, history, summarize) {
  const budget = historyBudget(system);
  // 1) summarize everything older than the recent window
  let msgs = await summarizeOld(history, 6, summarize);
  // 2) hard-fit under budget, protecting the summary + recent tail
  if (countAll(msgs) > budget) msgs = truncateOldest(msgs, budget);
  return [system, ...msgs];              // system is pinned, always first
}

// reuse it on every turn — history grows, the window never overflows:
async function ask(system, history, q, summarize) {
  history.push({ role: "user", content: q });
  const messages = await manageContext(system, history, summarize);
  const r = await generateText({ model, messages });
  history.push({ role: "assistant", content: r.text });
  return r.text;
}
