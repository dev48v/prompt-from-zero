PromptFromZero · Day 53

✏️ Chain-of-Draft (CoD) — a 2025 technique (Xu et al., Zoom) that keeps the step-by-step reasoning of Chain-of-Thought but forces every step to be a terse draft — a few words, an equation, a fragment — instead of a full explanatory sentence. The insight: on most reasoning tasks the tokens that actually carry the answer (the intermediate numbers, the one key transformation) are a tiny slice of a verbose CoT trace; the rest is fluent connective prose the model writes for the reader, not for itself. CoD strips that prose. You still get an explicit scratchpad — so the reasoning signal that makes CoT work is preserved — but at a fraction of the output tokens, cutting both cost and latency (the paper reports roughly 80% fewer reasoning tokens at accuracy close to CoT on arithmetic / commonsense / symbolic benchmarks). It sits between verbose CoT (maximal detail, maximal tokens) and direct answering (no reasoning, brittle on multi-step): terse drafts are the sweet spot where the model still shows its work to itself but stops narrating. Distinct from context management (D52 — fitting the input history into the window); CoD shrinks the model's output reasoning.

🔑 Chain-of-Draft keeps the reasoning, drops the narration. Chain-of-Thought works because it externalises the intermediate steps — writing them down gives the model a scratchpad to compute against instead of guessing an answer in one leap. But CoT writes those steps as fluent prose for a human reader, and that prose is where most of the tokens go: on the problems above, the numbers and the single key equation that actually decide the answer are only a handful of tokens; the rest is connective tissue (“To find how many he gave away, we need to calculate the difference between…”). Chain-of-Draft caps each step to a few words, so it keeps the same intermediate state — the same scratchpad that makes CoT reliable — while cutting the narration. The result is the same answer at a fraction of the output tokens, which directly lowers cost and latency (fewer tokens to generate). The trade-off is real but narrow: if a step is squeezed so hard it drops the signal, or the model is very small and can't hold the state implicitly, accuracy can dip — which is why CoD is prompted with a clear terse-format instruction (and often a one-shot example) rather than left to chance. Distinct from context management (D52, the input side) — CoD is about making the model's output reasoning lean.

🔨 Build it yourself

    
Chain-of-Draft is a prompt-only technique — no fine-tune, no extra model call. You keep everything about a Chain-of-Thought pipeline and change one thing: the instruction that tells the model to reason in terse drafts and mark the final answer after a delimiter. Here it is end to end, provider-portable (Vercel AI SDK's system + messages, which map to Anthropic and OpenAI alike), with the token measurement that proves the savings and the copy-paste system-prompt template.

    
    
      
  1. 
        
    1
    The idea in one line — cap every step to a few words
    
        
    Chain-of-Thought says “think step by step”. Chain-of-Draft adds a hard verbosity budget: still think step by step, but each step is a minimal draft — an equation, a number, a fragment — five words at most. The reasoning structure is identical; only the prose is removed. That single constraint is the whole technique.
    
        
    // CoT  →  narrated, one full sentence per step:
//   "To find how many he gave away, we subtract the
//    remaining lollipops from the starting amount, so..."
//
// CoD  →  minimal draft, a few words per step:
//   "start 20"
//   "left 12"
//   "20 - 12 = 8"
//   "#### 8"
//
// same steps, same answer — the narration is gone.
    
      
    2. 
      
  2. 
        
    2
    The CoD system prompt — the trigger
    
        
    The whole behaviour lives in one instruction (the paper's exact prompt). It does two jobs: cap the draft length so the model stops narrating, and require a delimiter before the final answer so you can parse it cleanly. Keep it in the system channel so it applies to every turn.
    
        
    // STEP 2 — the Chain-of-Draft instruction (verbatim from the paper).
const COD_SYSTEM =
  "Think step by step, but only keep a minimum draft for " +
  "each thinking step, with 5 words at most. Return the " +
  "answer at the end of the response after a separator ####.";

// contrast — the Chain-of-Thought instruction it replaces:
const COT_SYSTEM =
  "Think step by step to answer the question. Return the " +
  "answer at the end of the response after a separator ####.";
    
      
    3. 
      
  3. 
        
    3
    Wire it up — one call, terse output
    
        
    CoD is a drop-in swap for a CoT call — same SDK, same shape, only the system string changes. The model streams back a short draft trace plus the delimited answer. Because the output is smaller, both time-to-completion and cost drop with no pipeline change.
    
        
    // STEP 3 — same call as CoT; only the system prompt differs.
import { generateText } from "ai";
import { openai } from "@ai-sdk/openai";

async function askCoD(question) {
  const r = await generateText({
    model: openai("gpt-4o"),
    system: COD_SYSTEM,                                // ← the only change
    messages: [{ role: "user", content: question }],
  });
  return r.text;                                       // terse draft + #### answer
}
    
      
    4. 
      
  4. 
        
    4
    Parse the answer after the delimiter
    
        
    The #### separator is why CoD stays machine-usable despite the terse trace: split on it and take what follows. This is the same extraction you'd use for CoT — the delimiter, not the prose, is what your code depends on, so shrinking the reasoning changes nothing downstream.
    
        
    // STEP 4 — pull the final answer out from behind the separator.
function extractAnswer(text) {
  const i = text.lastIndexOf("####");
  const tail = i >= 0 ? text.slice(i + 4) : text;
  return tail.trim();                                  // "8"
}

const raw = await askCoD("Jason had 20 lollipops...");
const answer = extractAnswer(raw);                     // robust to terse traces

  5. 
        
    5
    Measure the savings — count the reasoning tokens
    
        
    Prove it, don't assume it. Run the same questions through CoT and CoD, count output tokens with the real tokenizer, and compare. Output tokens are what you pay for and what drives latency, so the CoD/CoT ratio is the number that matters — the paper sees CoD land near ~8% of CoT's reasoning tokens on GSM8K at comparable accuracy.
    
        
    // STEP 5 — quantify the reduction on your own tasks.
import { getEncoding } from "js-tiktoken";
const enc = getEncoding("cl100k_base");
const countTokens = (s) => enc.encode(s).length;

async function compare(question) {
  const cot = await askWith(COT_SYSTEM, question);
  const cod = await askWith(COD_SYSTEM, question);
  const tc = countTokens(cot), td = countTokens(cod);
  return {
    cotTokens: tc, codTokens: td,
    saved: `${Math.round((1 - td / tc) * 100)}%`,       // e.g. "80%"
  };
}
    
      
    6. 
      
  6. 
        
    6
    Guard the edges — one-shot the format, fall back on hard cases
    
        
    CoD can dip when a step is squeezed below the signal it needs to carry, or on very small models that can't hold state implicitly, or in strict zero-shot where the model ignores the terse instruction. The fixes are cheap: show one terse example so the format sticks, and route genuinely hard problems back to full CoT. Verbosity becomes a dial, not a fixed setting.
    
        
    // STEP 6 — anchor the terse format, and keep a CoT escape hatch.
const COD_ONESHOT = COD_SYSTEM + "\n\nExample —\n" +
  "Q: Jason had 20 lollipops, gave some, now has 12. How many?\n" +
  "A: start 20\n   left 12\n   20 - 12 = 8\n   #### 8";

async function solve(question, { hard = false } = {}) {
  const system = hard ? COT_SYSTEM : COD_ONESHOT;      // dial verbosity
  return extractAnswer(await askWith(system, question));
}
    
      
    7. 
      
  7. 
        
    7
    Compose — cheap self-consistency, and where it sits
    
        
    Because each CoD sample is ~5–10× cheaper than a CoT sample, you can afford to draw more of them and majority-vote (self-consistency, D3) for the accuracy of CoT at a fraction of the tokens. CoD is a reasoning-format technique — it swaps in under CoT (D2) and composes above voting. It's distinct from context management (D52, shrinking the input); CoD shrinks the output reasoning. Next: evaluation — regression-testing outputs with promptfoo so a format change like CoD can't silently drop accuracy.
    
        
    // STEP 7 — terse drafts are cheap, so vote over many of them.
async function codSelfConsistency(question, n = 7) {
  const draws = await Promise.all(
    Array.from({ length: n }, () =>
      askWith(COD_SYSTEM, question).then(extractAnswer))
  );
  const tally = {};
  for (const a of draws) tally[a] = (tally[a] || 0) + 1;  // majority vote
  return Object.entries(tally).sort((x, y) => y[1] - x[1])[0][0];
}
// n CoD samples can cost less than ONE CoT sample — accuracy, cheaply.

  8. 
        
    📋
    Copy-paste — the CoD system-prompt template
    
        
    Drop this straight into your system field. The first line is the paper's canonical trigger; the rest hardens the format and keeps it parseable.
    
        
    You are a careful reasoner. Think step by step, but only keep a
MINIMUM DRAFT for each thinking step — 5 words at most per step.
Do not write full sentences or explanations; use fragments,
numbers, and equations only. One draft step per line.
After the final step, output a line with the separator #### followed
by the final answer only (no units, no extra words).

Example —
Q: A shirt costs $40 after a 20% discount. Original price?
A: 0.8*x = 40
   x = 40 / 0.8
   x = 50
   #### 50
