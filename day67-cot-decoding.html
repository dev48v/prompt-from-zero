PROMPTFROMZERO · DAY 67

🌿 CoT-decoding — sixty-six days of this series changed the prompt. Wang & Zhou (2024) point out that the reasoning was often already there and greedy decoding was throwing it away: take the top-k first tokens instead of the argmax one, decode each greedily, and several of those branches turn out to contain a chain of thought that no instruction asked for. Then pick between them by the confidence gap over the answer span — Δ = p(top-1) − p(top-2), averaged over the answer tokens only. This page simulates the branch population and the confidence readout, never the language, and prices the result: greedy 39.6% → 75.9%. And then the control that cost the page its headline — "just take the longest branch", which needs no logprobs at all, scores 76.2%. The confidence gap earns its keep somewhere else entirely, and the page measures where. Pure vanilla JavaScript, one file, offline.

4,000 questions per render, seeded. Nothing here generates text — what is simulated is the population of decoding branches and the confidence readout attached to each.

Zero when every branch is right, zero when every branch is wrong, and a peak in between. A headline "+36 points" is not portable — it is a statement about the benchmark it was measured on.

OVERCONFIDENCE: A CONSTANT THAT DOES NOT WASH OUT

Adding a constant to every Δ cannot change an argmax — until the readout clips. A probability gap cannot exceed 1, so the branches you most wanted to separate merge into a tie, and the tie breaks to the lowest rank, which is the greedy branch you were trying to escape. The last column is the twist: a weighted sum is not shift-invariant, so the same constant that max-Δ cannot see drags Δ-weighted voting toward plain majority.

IN-PAGE SELF-TEST


      


    

  






  

    


      
The prompt was never the only place to intervene


      
Every technique in this series so far has been a change to the text you send. CoT-decoding
      is not. The prompt stays exactly as it was — no "let's think step by step", no exemplars, no
      system message — and the change happens one layer down, in how the tokens come out.


      
Greedy decoding takes the highest-probability first token and never looks back. Wang &
      Zhou's observation is that for a question with an obvious-looking answer, that first token is
      very often the start of the answer, and committing to it forecloses the reasoning.
      The alternative first tokens — ranks 1 through k−1, which greedy discards — much more often
      open a path that works through the problem first.


      

        
So the reasoning ability was already in the model. What "let's think step
        by step" does, on this reading, is not teach reasoning — it makes the reasoning
        branch the argmax. Which is a much less magical description of prompting, and a more useful
        one.

      


      
Two problems, and only the second one is interesting


      
Branching is easy: ask for the top k first tokens, then greedy-decode k continuations.
      Choosing is the hard part, because you now have k answers and no labels. The
      paper's selector is the model's own confidence — specifically the gap between the top two
      token probabilities, Δ = p(top-1) − p(top-2), averaged over the answer tokens.


      
Two details in that sentence are doing all the work:


      
    
        
  • Over the answer span, not the whole path. A reasoning path is 20–100
        tokens of fluent prose and 3 tokens of answer. Average Δ over all of it and the fluency
        drowns the signal — and it drowns it more the better the reasoning is, because the
        good paths are the long ones. Measured on this page: 75.9% over the answer span, 67.5% over
        the path. The naive version is worse than the free control.
    • 
        
  • Δ, not a verbalised confidence. Day 54 asked the model to say
        how sure it was. This reads a quantity the model never states and cannot editorialise —
        which also means it needs logprob access, and most hosted APIs do not give you a top-2
        probability per token.
    • 
      


      
🔴 The control that took the headline


      
The page was going to say: the confidence gap is what finds the reasoning path. So it
      needed a floor — a selector that also finds reasoning paths but reads no probabilities at all.
      Pick the longest branch. Reasoning paths are long; direct answers are short.
      It is one line and it is free.


      
At the default settings it scores 76.2% against max-Δ's
      75.9%. Dead level. The whole apparatus of logprob access, answer-span
      localisation and per-token arithmetic bought nothing over argmax(len).


      
That is the honest headline, and the interesting question is where it stops being true.
      Two places, both measured:


      
    
        
  • k. "Longest" saturates at the accuracy of a reasoning branch, because
        once it reliably finds one, more branches give it nothing new — 75.2% at k=8 and 76.3% at
        k=30. Δ keeps going, because it discriminates between reasoning branches: 72.8% at
        k=8, 82.2% at k=30. The value of the confidence signal is in the slope, not the
        level.
    • 
        
  • ρ. How much of the correctness margin the confidence actually carries.
        Below about 0.5, max-Δ is worse than picking the longest branch; above it, better. Every
        published Δ result is implicitly a claim about ρ for that model on that task, and it is not
        a portable constant.
    • 
      


      
And the selector that wins nearly everywhere is neither: Δ-weighted voting,
      at 82.2%. Vote like self-consistency, but weight each vote by that branch's answer confidence.
      It uses both signals and fails gracefully when either one dies.


      
Two selectors, two orthogonal failure modes


      
This is the part worth taking away, because it tells you which one to reach for:


      
    
        
  • Majority voting fails when the errors agree. It needs the right answer
        to be modal. Push every wrong branch onto one attractor — the answer you get from the
        plausible-but-wrong method — and voting elects it: 78.3% → 52.9% across the sweep. Max-Δ
        does not move (78.1% → 75.7%), because it never looks at the other branches.
    • 
        
  • Δ-ranking fails when the confidence is uninformative. At ρ = 0 it is
        56.5%, which is exactly picking at random. Majority voting sits flat at 74.0% across that
        whole sweep, because it never reads a confidence.
    • 
      


      
Neither failure is a bug in the technique. They are the two different things a selector can
      be made of — agreement between samples, or a signal inside one sample — and they break for
      unrelated reasons. Which is also why weighting one by the other is not a hack.


      
The Day-65 lesson, arriving from the other side


      
Day 65 spent three attempts learning that an additive constant in a score is exactly what
      calibration removes. Here the same constant shows up as overconfidence —
      real models report high probability gaps everywhere — and the arithmetic says it must be
      invisible, because adding a constant to every Δ cannot reorder an argmax.


      
The page asserts that, and it is exact: with the readout left unclipped, +0.25 changes the
      result by 0.00e+0 — and so does +4.00, and so does +1000. Then it clips,
      because a probability gap is bounded by 1, and the same +0.25 costs 6.3
      points — 75.5% → 69.2% — with 75.2% of questions ending in a tie at the top. The tie
      breaks to the lowest rank. The lowest rank is the greedy branch. Overconfidence quietly hands
      you back the branch you branched to avoid.


      
Then the verifier found the sharper version, which I had asserted wrongly and had to
      correct. "A constant is invisible" is true of an argmax and false of a
      weighted sum: adding c to every Δ adds c × (number of votes) to each answer's total,
      so the constant is really a knob that turns Δ-weighted voting into plain majority voting.
      Unclipped, with no ties and no clipping anywhere, +0.25 leaves max-Δ at exactly 75.9% — bit
      for bit the undisturbed number — and moves the weighted vote 82.2% → 80.5%, converging at
      77.6%. Its limit
      is not plain majority (74.4%) but majority with Δ used only to break ties, and that tie-break
      alone is worth 3.2 points.


      

        
So the Day-65 rule needs a qualifier. A constant bias washes out of any
        selector that only reads the order of the scores. It does not wash out of one that
        reads their magnitudes — and it does not wash out of an ordering either, once the
        scale it lives on has an edge to pile up against.

      


      
The columns nobody quotes


      
k branches is k decodes. At k=10 that is 10 calls instead of 1, 439 output tokens instead
      of 25, and 2,239 total tokens instead of 205. Three things about that bill:


      
    
        
  • Most of it is the prompt, sent ten times — 1,800 of the 2,239. Prefix
        caching removes nearly all of that, so the irreducible cost is the output side: 17.6×.
    • 
        
  • Latency is not 10×. The branches are independent, so wall-clock is the
        longest branch, not the sum: 97 tokens against greedy's 25. You pay 3.9× in time
        and 17.6× in output tokens, and those are different budgets.
    • 
        
  • The number to actually compare is tokens per additional correct answer.
        Δ-weighted voting is the cheapest at ~974 output tokens per extra correct answer; max-Δ is
        1,140; plain majority 1,190. All are in the same order of magnitude, which is the real
        finding — the selectors differ by a few points, not by a factor.
    • 
      


      
Where this model is a stand-in, said plainly


      
Declared, not derived: the probability that a branch at rank r contains reasoning (0.12 at
      the greedy rank, saturating to 0.66 — this is the paper's empirical observation, and the page
      includes a control that flattens it, at which point greedy and a random branch score the same
      62%); how much a reasoning path adds to the correctness margin; the length distributions; and
      ρ. Measured, not declared: everything in every table — which selector wins where, the
      crossovers, the saturation of "longest", the clipping cost, and the whole cost column.


      
The one number to distrust hardest is the 39.6% → 75.9% headline. It is a property of a
      difficulty mix, and the sweep shows the same technique paying 0.0 points at the easy end and
      0.2 points at the hard end.


    

  






  

    


      
🔨 How it is built


      
1. The one modelling decision everything rests on

      
Confidence must not be a readout of correctness. The first version of this
      engine set Δ = sigmoid(margin) + noise, and since correctness is margin > 0,
      that made Δ a nearly noiseless report of the answer being right — max-Δ measured
      100.0%, identical to the oracle, on every setting. Correct arithmetic, useless
      page. The fix is a shared latent with a dial-able weight:

      
function confidence(m, rho, c, rnd){
  // rho = how much of the correctness margin the probability gap carries.
  // rho=0 -> pure fluency, independent of being right.  rho=1 -> a perfect readout.
  const carried = rho * m + Math.sqrt(1 - rho * rho) * c.confSpread * gauss(rnd);
  const raw = sigmoid(c.answerSlope * carried) + c.overconfidence;
  return c.clampConfidence === false ? raw : clamp01(raw);
}

      
Now ρ is a dial with two honest endpoints — random selection at 0, oracle at 1 — and the
      page's job is to find where on that dial the technique stops being worth its dependencies.


      
2. The branch population

      
// declared from the paper: the argmax first token is the LEAST likely to open a
// reasoning path, and the rate saturates as you go down the ranks.
function pCot(rank, c){
  return rank === 0 ? c.cotAtGreedy
    : c.cotAtGreedy + (c.cotCeiling - c.cotAtGreedy) * (1 - Math.exp(-rank / c.cotRankScale));
}

const isCot  = rnd() < pCot(r, c);
const margin = c.skill + (isCot ? c.cotBonus : 0) - difficulty + c.spread * gauss(rnd);
const correct = margin > 0;

      
Saturating on purpose. A term that grows without bound is a term that will eventually carry
      a claim it cannot support, and rank 12 is not meaningfully more likely to reason than rank 8.
      The control that keeps this honest is cotAtGreedy = cotCeiling: flatten the
      profile and greedy lands on top of a random branch — both near 62%, the exact pair printed by
      the self-test panel — which is the proof that the greedy penalty on this page is entirely
      that one declared curve and not an artefact of anything else in the engine.


      
3. Δ over the answer span vs Δ over the path

      
const ansTokens = 2 + Math.floor(rnd() * 4);
const reaTokens = isCot ? 18 + Math.floor(rnd() * 92) : 4 + Math.floor(rnd() * 24);

deltaAnswer: dAns,
deltaPath:   (dRea * reaTokens + dAns * ansTokens) / (reaTokens + ansTokens)

      
A token-weighted mean, which is what "average Δ over the generation" means. The dilution is
      not a coefficient someone tuned — it falls out of 3 answer tokens against 60 reasoning ones,
      and it gets worse as reasoning gets longer.


      
4. Eight selectors, including the ones meant to lose

      
const SELECTORS = {
  greedy:      b => b[0].answer,                              // the baseline
  randomPath:  (b, c, u) => b[Math.floor(u * b.length)].answer, // the floor
  longest:     b => argmaxBy(b, x => x.tokens).answer,        // free, no logprobs
  deltaPath:   b => argmaxBy(b, x => x.deltaPath).answer,     // the naive mistake
  deltaAnswer: b => argmaxBy(b, x => x.deltaAnswer).answer,   // CoT-decoding
  majority:    b => modalAnswer(b),                           // self-consistency
  weighted:    b => modalAnswer(b, x => x.deltaAnswer),       // both signals
  oracle:      b => b.some(x => x.correct) ? 0 : b[0].answer  // the ceiling
};

      
randomPath and oracle are the two that make the rest readable:
      every other selector is reported as the fraction of the floor-to-ceiling gap it captures, so
      "76%" turns into "half of what was available". longest is the control that took
      the headline, and it is on the page because a technique with dependencies has to beat the
      version without them, not just beat doing nothing.


      
5. The cost side is counted, not asserted

      
// k branches is k decodes. Prompt tokens are paid k times unless the prefix is cached;
// output tokens always. Latency is the LONGEST branch, because they run independently.
tokens   += sum(branch.tokens) + c.promptTokens * c.k;
serial   += sum(branch.tokens);
parallel += max(branch.tokens);

// and the column that makes the comparison fair:
tokensPerExtraCorrect = (tokens - greedyTokens) / (accuracy - greedyAccuracy);


      
6. What the tests pin

      
// the shape of the thing
assert(acc(k=1) === acc(greedy));                    // no branches, no technique
assert(acc(rho=0) ≈ acc(randomPath));                // a useless Δ selects nothing
assert(acc(rho=1) ≈ acc(oracle));                    // a perfect Δ is the ceiling
assert(acc(deltaAnswer) > acc(deltaPath));           // the span matters

// the controls
assert(|argmaxAcc(over=0.25, unclipped) - argmaxAcc(over=0)| === 0);  // EXACTLY, not approximately
assert(acc(over=0.25, clipped)  <  acc(over=0));           // clipping is the whole effect
assert(weightedAcc(over=0.25)   <  weightedAcc(over=0));   // a SUM is not shift-invariant
assert(|acc(greedy) - acc(random)| < 0.04) when pCot is flat;

// the honest ones
assert(acc(longest) >= acc(deltaAnswer) - 0.02) at the defaults;  // the null result
assert(slope_k(longest) < slope_k(deltaAnswer));                   // where it stops
assert(gain(easiest) < 0.02 && gain(hardest) < 0.02);             // both ends of the U

      
The third-from-last is the one that hurt. It asserts that at the page's own default
      settings the free heuristic is not beaten by the technique the page is about. Writing
      a test that pins your own null result is the only way it survives the next edit.


      
And the weighted-sum line above it exists because the first version of that assertion said
      for every selector: acc(over=0.25) === acc(over=0) and one of the nine failed.
      The engine was right and the test was wrong, which is the good direction for that to happen
      in — the finding on the UNDERSTAND tab is what the failure turned into.
