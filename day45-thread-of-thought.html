PromptFromZero · Day 45

🧵 Thread of Thought (ThoT) — when the context is long, chaotic and multi-part, dumping it all in one blob and asking makes the model skim: it attends hardest to the start and end and loses the fact buried in the middle. ThoT fixes it with one instruction — “walk me through this context in manageable parts, summarizing and analyzing as we go, then answer”. The model reads segment by segment, writes a mini-summary of each, carries a running thread forward, and only then synthesizes — so scattered, buried info actually surfaces.

Watch a one-shot read miss a decision buried mid-thread — then watch the model walk the context part by part and pin it.

Long inputs have a well-known flaw: models suffer “lost in the middle” — attention is strongest at the beginning and end of the context and weakest in the center, so a key fact sitting mid-way gets skimmed past while a louder distractor at an edge wins. Thread of Thought beats it not by shortening the input but by changing how it's read: a single instruction tells the model to segment → summarize each part → carry a running thread → then answer. Every part now gets equal, deliberate attention and its takeaway is written down, so the buried fact can't vanish. Everything below is real: the per-chunk relevance score, the date extractor, the finality detector, the running thread, and both answers are computed live in JS. Flip Thread of Thought on to watch the model walk the thread; drag the buried decision to a different position and watch the one-shot answer flip with it while the ThoT answer stays locked on the fact.

🔑 Thread of Thought = don't read a long context in one gulp — walk it in parts, summarize each, keep a running thread, then answer. Because a model's attention over a long input is uneven (strong at the ends, weak in the middle), a single-pass read quietly drops facts buried mid-context. ThoT is chain-of-thought applied to reading instead of just reasoning: one zero-shot instruction — “walk me through this context in manageable parts, summarizing and analyzing as we go” — makes the model give each segment its own deliberate pass and externalize a mini-summary, so nothing depends on where it happened to sit. It costs no extra API call (it's a prompt change, not a pipeline) and it shines exactly where inputs are long, chaotic, multi-document, or needle-in-a-haystack.

🔨 Build it yourself

    
Thread of Thought is a prompt, not a pipeline: walk the context in parts → summarize each → carry a running thread → then answer. No extra API call, no retriever. Here it is end to end — the naive one-shot, why plain CoT isn't enough, the ThoT trigger phrase, segmenting the context, the walk with per-part summaries, the running thread + synthesis, and when the technique earns its place.

    
    
      
  1. 
        
    1
    The naive pipeline — dump the whole context & ask
    
        
    The default is one shot: paste the entire long context plus the question and take the answer. It's fine for short, tidy inputs — but on a long chaotic thread the model's attention is uneven (strong at the ends, weak in the middle), so a fact buried mid-context gets skimmed past and a louder edge detail wins. This is the behaviour we want to beat.
    
        
    // STEP 1 — the ordinary one-shot answer. Skims long inputs.
const answer = await llm(`Context: """${context}"""
Question: ${question}`);
// works... until the context is long and the key fact sits in
// the middle. "Lost in the middle" -> the buried fact is dropped.
    
      
    2. 
      
  2. 
        
    2
    Why plain “think step by step” isn't enough
    
        
    The obvious upgrade is chain-of-thought — but CoT segments the reasoning, not the reading. It still consumes the context as one undivided blob in a single pass, so a fact it never noticed can't enter the reasoning at all. Better logic over a skimmed input is still an answer built on a gap. ThoT's move is to segment the input, not just the thoughts.
    
        
    // STEP 2 — CoT: better reasoning, same one-pass read.
const answer = await llm(`Context: """${context}"""
Question: ${question}
Let's think step by step.`);
// the reasoning is structured, but the CONTEXT was still read in
// one gulp -> a mid-context fact it skimmed never reaches the logic.
    
      
    3. 
      
  3. 
        
    3
    The ThoT trigger — one zero-shot line
    
        
    The whole technique is a single instruction appended to the prompt: “Walk me through this context in manageable parts step by step, summarizing and analyzing as we go.” That phrase makes the model split the context itself, give each part a deliberate pass, and write down what it found — no examples, no extra calls. It's the ThoT paper's exact zero-shot prompt.
    
        
    // STEP 3 — the ThoT trigger phrase (zero-shot, one line).
const THOT = "Walk me through this context in manageable parts " +
             "step by step, summarizing and analyzing as we go.";

const walk = await llm(`Context: """${context}"""
Question: ${question}
${THOT}`);
// one instruction -> segment + summarize each part + carry forward.
    
      
    4. 
      
  4. 
        
    4
    Segment the context into manageable parts
    
        
    Conceptually the first thing ThoT does is cut the long context into parts — by message, paragraph, section, or a fixed window. You can let the model do it implicitly from the trigger phrase, or split explicitly in code for tighter control. Each part is small enough to get full attention on its own pass, which is exactly what defeats “lost in the middle”.
    
        
    // STEP 4 — segment (implicit via the phrase, or explicit in code).
const parts = context.split(/\n{2,}/);   // by paragraph/message
// now each `parts[i]` is short enough to read with full attention,
// instead of one 8k-token blob where the middle gets skimmed.
    
      
    5. 
      
  5. 
        
    5
    Walk part by part — summarize & analyze each
    
        
    For every part the model writes a short summary and notes how it bears on the question — is this the fact, a superseded detail, or noise? The single ThoT call produces this walk in one response, but the mental (and code) model is a loop: read a part, summarize it, judge its relevance, move on. Writing each takeaway down is what stops the middle from disappearing.
    
        
    // STEP 5 — per-part: summarize + judge relevance to the question.
const notes = parts.map((p, i) => ({
  i,
  summary: summarize(p),               // one-line takeaway
  relevant: bearsOn(p, question)       // fact? superseded? noise?
}));
// each part got its OWN deliberate pass -> nothing skimmed away.
    
      
    6. 
      
  6. 
        
    6
    Carry a running thread → then synthesize
    
        
    The summaries accumulate into a running thread — a compact, externalized memory of everything relevant, in order. The final answer is synthesized from that thread, not from the raw blob. Because the thread already isolated the decisive fact and downgraded the distractors, the synthesis is short and correct. That's the full method: segment → summarize → thread → answer.
    
        
    // STEP 6 — Thread of Thought, end to end (still ONE call).
async function threadOfThought(context, question) {
  const THOT = "Walk me through this context in manageable parts " +
               "step by step, summarizing and analyzing as we go, " +
               "keep a running summary, then answer.";
  return llm(`Context: """${context}"""
Question: ${question}
${THOT}`);
}
// no extra call, no retriever -> just a smarter way to READ.

  7. 
        
    7
    When to reach for ThoT — and where it sits
    
        
    Thread of Thought (Zhou et al., 2023) targets chaotic, long-context tasks — messy conversation histories, multi-document QA, retrieval dumps where the answer hides among distractors. Use it whenever a fact could be buried in the middle of a big input. It's cheaper than retrieval-augmented pipelines (one prompt, no index) and complementary: it composes with RAG (walk the retrieved passages), and unlike plain CoT it segments the reading, not just the reasoning. Skip it for short, clean prompts where nothing is buried. Next: system prompts — the standing persona-and-rules turn that sets the model's role and hard constraints before the conversation begins.
    
        
    // STEP 7 — when ThoT earns its place.
// USE for:  long/chaotic context, multi-doc QA, messy chat history,
//           retrieval dumps, "needle in a haystack" lookups.
// SKIP for: short clean prompts (nothing buried), single-fact recall.
//
// vs CoT : CoT segments the REASONING; ThoT segments the READING.
// vs RAG : RAG fetches less; ThoT reads what you already have, better.
