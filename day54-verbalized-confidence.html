PromptFromZero · Day 54

🎯 Verbalized Confidence — ask a model to state, in plain words, how sure it is (“Answer: Canberra — Confidence: 90%”), then check whether those stated numbers actually track how often it's right. A confidence is only worth anything if it's calibrated: of all the answers a model tags 90%, close to 90% should turn out correct. Language models are frequently over-confident — RLHF rewards replies that sound assured, so a raw model will happily stamp 95% on a coin-flip. This page makes that measurable: bin a labelled eval set by stated confidence, plot each bin's empirical accuracy against the y=x ideal (a reliability diagram), and read off the Expected Calibration Error (ECE) — the average gap between what the model says and what's true. Toggle between an over-confident model (curve sagging below the diagonal, high ECE) and a well-calibrated one (curve hugging the diagonal, low ECE) and watch the bend. Everything is baked-in and deterministic — no API key, no network. Distinct from Chain-of-Draft (D53, trimming the model's reasoning trace); verbalized confidence is about making its uncertainty explicit and honest.

Two models answer the same 20-question quiz and each states a confidence per answer. Bin those stated confidences, measure the real accuracy in each bin, and see how far the model's words drift from the truth.

Everything below is deterministic (no API key, no network): the answers, their stated confidences and their correct/incorrect flags are baked in, and the reliability diagram, the ECE and the per-bin table are all computed live from that data. A perfectly calibrated model would land every bin on the dashed y=x line — of the answers it tags 80%, exactly 80% are right. 🔑 A stated confidence is a promise the model doesn't always keep. Verbalized confidence is trivial to elicit — you just ask “how sure are you, 0–100%?” and parse the number — but the number is only useful if it's calibrated, i.e. the answers tagged 90% are right about 90% of the time. The reliability diagram tests exactly that: bin the predictions by stated confidence, plot each bin's real accuracy, and compare to the y=x line where confidence equals accuracy. The ECE collapses the whole diagram into one number — the count-weighted average distance from the diagonal. LLMs, especially raw or RLHF-tuned ones, skew over-confident: the curve sinks below the diagonal because the model says 95% when it's right 60% of the time — sounding sure is rewarded during training, being right about being unsure is not. The fix is partly prompt-craft (ask for a probability of being correct, give it permission to say low numbers, reserve 90%+ for bet-worthy answers) and partly measurement — you can't trust a confidence you've never scored against labels. Once calibrated, that number is gold: gate low-confidence answers to a human, route them to a bigger model, or abstain with an honest “I'm not sure.”

Verbalized confidence = the model states how sure it is; calibration = whether those numbers are true; ECE = one number for how far off they are.

🔨 Build it yourself

    
Verbalized confidence is a prompt-only technique to elicit the number, plus a small measurement harness to check it. You ask the model to append a confidence, parse it, and then — the part everyone skips — score it against labels with a reliability diagram and ECE so you know whether to trust it. Here it is end to end, provider-portable (Vercel AI SDK's system + messages, which map to Anthropic and OpenAI alike), with the exact calibration math the demo above runs and a copy-paste elicitation template.

    
    
      
  1. 
        
    1
    The idea in one line — ask for the answer AND a confidence
    
        
    Instead of just an answer, you ask the model to attach an explicit self-estimate of how likely that answer is to be correct, as a percentage. That single extra line turns an opaque guess into a signal you can act on — if the number is honest. The whole rest of the technique is about verifying that “if”.

  2. 
        
    2
    The elicitation prompt — the trigger
    
        
    The behaviour lives in one system instruction. It does three jobs: ask for a probability of being correct (not vibes), give the model explicit permission to say low numbers so it isn't pushed to sound sure, and fix a rigid output shape so you can parse it. Keep it in the system channel so it applies every turn.
    
        
    // STEP 2 — the confidence-elicitation instruction.
const CONF_SYSTEM =
  "Answer the question, then state how confident you are that " +
  "your answer is CORRECT, as a percentage from 0 to 100. " +
  "Base it on how likely you are to be right, not on how sure " +
  "you want to sound; if you are guessing, use a low number. " +
  "Reserve 90-100% for answers you would bet on; use 50% for a " +
  "coin-flip. Output exactly:\n" +
  "Answer: <answer>\nConfidence: <0-100>%";
    
      
    3. 
      
  3. 
        
    3
    Wire it up & parse — pull out answer + confidence
    
        
    Same call shape as any other prompt; only the system string changes. Because the format is fixed, a couple of regexes recover the answer and the number. Clamp to 0–100 and default sensibly if the model forgets the line, so a stray format never crashes the pipeline.
    
        
    // STEP 3 — one call, then parse the two fields.
import { generateText } from "ai";
import { openai } from "@ai-sdk/openai";

async function askWithConfidence(question) {
  const r = await generateText({
    model: openai("gpt-4o"),
    system: CONF_SYSTEM,
    messages: [{ role: "user", content: question }],
  });
  return parseConfidence(r.text);
}

function parseConfidence(text) {
  const ans  = (text.match(/Answer:\s*(.+)/i)     || [,""])[1].trim();
  const confM =  text.match(/Confidence:\s*(\d+(?:\.\d+)?)\s*%?/i);
  let conf = confM ? parseFloat(confM[1]) : 50;   // default: coin-flip
  conf = Math.max(0, Math.min(100, conf));         // clamp
  return { answer: ans, confidence: conf };
}
    
      
    4. 
      
  4. 
        
    4
    Bin the predictions by stated confidence
    
        
    To test calibration you need a labelled eval set — questions where you know the true answer. Score each prediction correct/incorrect, then drop it into a confidence bucket (here 10-point bins). Each bin will give you two numbers: the mean confidence the model stated, and the accuracy it actually achieved.
    
        
    // STEP 4 — group predictions into confidence bins.
// preds: [{ confidence: 0-100, correct: boolean }, ...]
function binByConfidence(preds, width = 10) {
  const nb = Math.round(100 / width);
  const bins = Array.from({ length: nb }, (_, i) => (
    { lo: i * width, hi: (i + 1) * width, confs: [], correct: 0, n: 0 }));
  for (const p of preds) {
    let idx = Math.floor(p.confidence / width);
    if (idx >= nb) idx = nb - 1;                   // 100% → last bin
    const b = bins[idx];
    b.n++; b.confs.push(p.confidence);
    if (p.correct) b.correct++;
  }
  for (const b of bins) {
    b.acc      = b.n ? b.correct / b.n : 0;                     // y
    b.meanConf = b.n ? b.confs.reduce((s, c) => s + c, 0) / b.n / 100 : 0; // x
    b.gap      = Math.abs(b.acc - b.meanConf);
  }
  return bins;
}
    
      
    5. 
      
  5. 
        
    5
    Compute ECE — one number for the whole diagram
    
        
    Expected Calibration Error is the count-weighted average of every bin's gap between stated confidence and accuracy. It's exactly the reliability diagram collapsed to a scalar: 0 means every bin sits on the diagonal (perfect), and bigger means the model's words drift further from reality. This is the identical math the demo's readout runs.
    
        
    // STEP 5 — ECE = Σ (n_bin / N) · |accuracy − confidence|.
function expectedCalibrationError(preds, width = 10) {
  const N = preds.length;
  const bins = binByConfidence(preds, width);
  return bins.reduce((ece, b) =>
    ece + (b.n ? (b.n / N) * Math.abs(b.acc - b.meanConf) : 0), 0);
}

// overconfident model  → ECE ≈ 0.40  (claims ~85%, right ~50%)
// well-calibrated model → ECE ≈ 0.06  (claims ~75%, right ~75%)
const ece = expectedCalibrationError(myPreds);   // 0 = perfect

  6. 
        
    6
    Read the direction — over- vs under-confident
    
        
    The sign of the gap tells you which way the model is wrong, and the fix differs. Accuracy below stated confidence (points below the diagonal) is over-confidence — the common LLM failure; accuracy above is under-confidence. A cheap post-hoc correction is a global scale (a verbalized cousin of temperature scaling) fit on a validation split.
    
        
    // STEP 6 — diagnose direction, then optionally rescale.
function diagnose(preds) {
  const acc  = preds.filter(p => p.correct).length / preds.length;
  const conf = preds.reduce((s, p) => s + p.confidence, 0) / preds.length / 100;
  const skew = conf - acc;                         // + = overconfident
  return skew > 0.05 ? "overconfident"
       : skew < -0.05 ? "underconfident"
       : "calibrated";
}

// post-hoc: shrink stated confidences toward accuracy on a val set.
const scaled = p => ({ ...p,
  confidence: 100 * (acc + k * (p.confidence / 100 - acc)) }); // fit k≤1
    
      
    7. 
      
  7. 
        
    7
    Elicit better numbers — and act on them
    
        
    Two levers improve raw calibration before any rescaling. Prompt-side: ask for a probability of being correct, permit low numbers, and optionally have the model list the top-2 answers with probabilities that sum to 1. Sampling-side: draw N samples and use answer agreement as an empirical confidence (self-consistency, D3) — often better calibrated than the model's own words. Then the payoff: threshold on confidence to abstain, escalate, or route.
    
        
    // STEP 7 — agreement-based confidence, then act on the number.
async function sampledConfidence(question, n = 8) {
  const outs = await Promise.all(Array.from({ length: n },
    () => askWithConfidence(question)));
  const tally = {};
  for (const o of outs) tally[o.answer] = (tally[o.answer] || 0) + 1;
  const [answer, votes] = Object.entries(tally).sort((a, b) => b[1] - a[1])[0];
  return { answer, confidence: 100 * votes / n };  // empirical agreement
}

async function answerOrAbstain(q, floor = 70) {
  const { answer, confidence } = await sampledConfidence(q);
  if (confidence < floor) return { action: "escalate", answer, confidence };
  return { action: "answer", answer, confidence };  // trust the calibrated %
}

    Copy-paste — the confidence-elicitation template
    
        
    Drop this straight into your system field. It asks for a probability of being right, gives explicit permission to be unsure, anchors the scale, and fixes a parseable format.
    
        
    You are a careful assistant. Answer the question, then state how
confident you are that your answer is correct, as a percentage
from 0 to 100.

Rules:
- Base the number on how likely you are to be RIGHT, not on how
  sure you want to sound. If you are guessing, say so with a low
  number — being honestly unsure is correct behaviour, not a failure.
- Reserve 90-100% for answers you would bet money on. Use 50% for a
  true coin-flip. Spread the rest in between.
- Do not default to a round, confident-sounding number.
- Output EXACTLY this and nothing else:

Answer: <your answer>
Confidence: <0-100>%
